# ClearVision Consulting
# Component Library

Version 1.0

---

# Purpose

This document defines every reusable UI component used throughout the website.

Components should always be reused before new ones are created.

Consistency is more important than variety.

---

# Navigation

Purpose

Provide immediate orientation.

Behaviour

Sticky after scrolling.

Minimal.

Always visible.

Clear active state.

Never overloaded.

---

# Hero Section

Purpose

Create trust within the first five seconds.

Content

Headline

Supporting text

Primary CTA

Optional secondary CTA

Hero image or illustration

Never overload the Hero.

One message.

One goal.

---

# Section Header

Purpose

Introduce a new topic.

Structure

Eyebrow

Headline

Supporting paragraph

Optional CTA

Always maintain generous spacing.

---

# Buttons

Purpose

Guide interaction.

Types

Primary

Secondary

Text Button

Behaviour

Subtle hover.

Clear focus state.

Never oversized.

Never aggressive.

---

# Cards

Purpose

Group related information.

Characteristics

Generous padding.

Rounded corners.

Soft shadow.

Clear hierarchy.

Avoid excessive decoration.

---

# Service Card

Purpose

Explain one service.

Structure

Icon

Headline

Description

Optional CTA

Consistent height whenever possible.

---

# Feature List

Purpose

Present benefits clearly.

Always use

simple icons

short descriptions

consistent spacing

---

# Testimonial

Purpose

Build trust.

Structure

Quote

Name

Role

Practice

Photo (optional)

Authenticity is more important than quantity.

---

# FAQ

Purpose

Reduce uncertainty.

Structure

Question

Answer

Accordion behaviour

Questions should reflect real user concerns.

---

# Contact Form

Purpose

Reduce friction.

Only request information that is actually needed.

Provide clear labels.

Provide helpful validation.

Never overwhelm the user.

---

# Footer

Purpose

Provide orientation.

Include

Navigation

Contact

Legal information

Copyright

Keep the footer visually quiet.

---

# Animations

Purpose

Support orientation.

Preferred

Fade

Slide

Opacity

Transform

Avoid

Bounce

Rotate

Flash

Elastic

Motion should never distract.

---

# Empty States

Purpose

Explain what happens next.

Every empty state should provide guidance.

Never leave users without direction.

---

# Error Messages

Always explain

What happened

Why it happened

How the user can solve it

Avoid technical language.

---

# Loading States

Users should always receive feedback.

Prefer skeleton loaders over spinners whenever appropriate.

---

# Responsive Behaviour

Every component must work on

Mobile

Tablet

Desktop

Ultrawide

Components should adapt naturally.

Never create separate mobile components unless absolutely necessary.

---

# Accessibility

Every component must support

Keyboard navigation

Focus visibility

Screen readers

Accessible labels

Proper contrast

Accessibility is part of the component.

Not an optional enhancement.

---

# Final Principle

Every component should feel like it belongs to the same product.

If a component attracts attention to itself instead of the content,

it should be redesigned.
